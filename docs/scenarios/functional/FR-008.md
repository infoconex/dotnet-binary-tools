# FR-008: Human and JSON output

> **Retired draft:** Predates the approved [CAP-001–CAP-008 model](../../capabilities.md); not an active requirement. Historical IDs are reserved and never recycled.

**Specification status:** Superseded historical draft; not active acceptance criteria
**Priority:** Must
**Source:** [Functional requirements](../../requirements/functional.md)

## Purpose

Provide readable console output and parseable stable JSON for automation.

## Boundaries

This requirement does not authorize implementing dependent features early. Keep the declared framework distinct from SDK and executing runtime identity.

## Acceptance scenarios

### FR-008-SC01: Produce human-readable results

**Given** Given a scanned managed DLL with a known target,
**When** When default output is selected,
**Then** Then target identity and detection provenance are clearly visible.

### FR-008-SC02: Emit valid machine-readable JSON

**Given** Given a directory scan including at least one per-file error,
**When** When --format json is used,
**Then** Then stdout contains parseable structured JSON with stable fields and no diagnostic prose mixed into it.
