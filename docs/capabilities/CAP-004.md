# CAP-004: Lifecycle Assessment

**Specification status:** Approved for v0.1. **Implementation and acceptance:** Planned, not yet verified.

[Capability index](README.md)

This document explains the approved capability boundary. The [functional requirement catalog](../requirements/functional.md) and linked Given/When/Then scenarios provide the authoritative acceptance contract; explanations here must not expand it.

## Purpose

Provide dated, source-backed guidance on the published support lifecycle of a known declared .NET target or separately configured runtime requirement. The assessment is **advisory**: it is not a compliance determination and does not establish what runtime an application actually executes.

## Approved behavior

- **Offline by default:** Ship a local, versioned lifecycle reference dataset with identifiable authoritative sources, coverage, and publication/update information. Routine `inspect` and `scan` operations do not access the network.
- **Assess distinct facts:** Evaluate recognized .NET Framework, .NET Core, and modern .NET identities against applicable published support information. Evaluate a configured runtime request separately from an assembly target, even when the two differ.
- **Respect product models:** .NET Standard is an API specification, not an installed runtime with its own runtime lifecycle. Unknown, future, or unsupported-to-classify versions remain explicitly uncertain; never make up an end-of-support date.
- **Dated provenance:** Include assessment date, source, dataset version, source publication/fetch dates, coverage or applicability limitations, and freshness warnings with each relevant finding.
- **Advisory outcomes:** Clearly describe the status and uncertainty without claiming actual application compliance or changing command success merely because a version is out of support.
- **Explicit online refresh:** Download updates only through a separately requested refresh operation using approved authoritative sources. Validate the replacement and atomically adopt it only when complete and trusted.
- **Safe refresh failure:** Retain the last known valid dataset on download, validation, or replacement failure; report a warning and the provenance of the data actually used.

## Inputs and outputs

Consumes an explicitly evidenced framework identity from [CAP-002](CAP-002.md), a configured runtime request from [CAP-003](CAP-003.md), and the validated local lifecycle dataset. Produces advisory findings with sufficient references and dates for a reader to understand why they were reported.

## Boundaries and exclusions

No claims about installed runtimes, running processes, actual app compatibility, security vulnerability exposure, or compliance. Do not equate assembly target support with configuration runtime support or treat stale/unavailable reference data as current certainty.

## Failure and completeness behavior

If a target cannot be confidently classified, report its status as unknown or not assessed with the reason. Failure to refresh must not discard verified cached reference data or trigger a hidden network fallback.

## Open implementation decisions

The exact freshness threshold, source allowlist, data-integrity rules, and cache details are [open technical decisions](../requirements/open-decisions.md), not approved numerical defaults.

## Related capabilities

[CAP-002](CAP-002.md) and [CAP-003](CAP-003.md) provide distinct facts; [CAP-006](CAP-006.md) exposes lifecycle provenance and limitations without filtering them away.

| [FR-LCY-002](../scenarios/functional/lifecycle-assessment/FR-LCY-002.md) | Assess declared target lifecycle | Assess known .NET Framework, .NET Core and modern .NET target identities using dated published support information, subject to source-specific applicability limits. |

| [FR-LCY-008](../scenarios/functional/lifecycle-assessment/FR-LCY-008.md) | Preserve valid data after refresh failure | On refresh failure, preserve last known valid data, warn about the failure and mark assessment provenance honestly; never install partial or untrusted data. |
