# CAP-003: Deployment Configuration

**Specification status:** Approved for v0.1. **Implementation and acceptance:** Planned, not yet verified.

[Capability index](README.md)

This document explains the approved capability boundary. The [functional requirement catalog](../requirements/functional.md) and linked Given/When/Then scenarios provide the authoritative acceptance contract; explanations here must not expand it.

## Purpose

Describe runtime requirements explicitly stated in an application's supported deployment configuration. Configuration is a separate evidence source from an assembly's declared target framework, and neither proves what is installed or running.

## Approved behavior

- **Constrained discovery:** Automatically consider only supported configuration filenames directly associated with the selected file. The initial scope includes .NET Framework `*.exe.config` and modern `*.runtimeconfig.json` forms; do not search arbitrary neighboring directories or guess which application owns a DLL.
- **Explicit selection:** For an individual `inspect` request, accept a supported configuration path supplied using `--config`, validate it, and identify that it was explicit rather than automatically discovered. A single configuration path is **not** applied to all candidates in `scan`.
- **Legacy runtime declarations:** Extract supported `startup` / `supportedRuntime` declarations, including available `version` and `sku` values, preserving what the configuration actually says.
- **Modern runtime declarations:** Parse applicable `runtimeOptions` fields: TFM, `framework` / `frameworks` names and versions, and declared runtime-selection policies.
- **Provenance:** Report configuration path, association mode, and the originating configuration field so consumers can distinguish observed declarations from assumptions.
- **No invented defaults:** Show "not found" when no supported configuration is discovered. Do not infer a required runtime from that absence, nor from the assembly's target moniker.
- **Separation of facts:** Preserve configured runtime requirements independently of [CAP-002](CAP-002.md) assembly targets, including when their values conflict.

## Inputs and outputs

Consumes the inspected file context and, optionally, one validated explicit configuration file. Emits configuration-specific runtime request records, source references, or a clear absent/invalid finding. These records can inform [CAP-004](CAP-004.md) without replacing the assembly's own target information.

## Boundaries and exclusions

No installed-runtime inventory, process inspection, application-host inference, scanning for unrelated configuration, or verification that a configured runtime will be selected successfully. Configuration is parsed as data; it must not cause executable code to run.

## Failure and completeness behavior

Separate **not found**, **malformed**, **unsupported**, and **unreadable** configuration outcomes. Report useful diagnostics and preserve provenance rather than silently substituting the target framework. A configuration failure remains visible in [CAP-006 reports](CAP-006.md).

## Related capabilities

[CAP-001](CAP-001.md) validates explicit paths; [CAP-002](CAP-002.md) supplies assembly target evidence; [CAP-004](CAP-004.md) assesses runtime lifecycle; [CAP-006](CAP-006.md) presents both declarations without conflation.
