# CAP-001: Input Selection

**Specification status:** Approved for v0.1. **Implementation and acceptance:** Planned, not yet verified.

[Capability index](README.md)

This capability document defines the approved requirement wording in its **Requirement coverage** table. The linked Given/When/Then scenarios define acceptance; explanatory material here must not expand the approved scope. [Functional requirements index](../requirements/functional.md).

## Purpose

Establish a trustworthy, explicit set of file or directory inputs *before* any inspection or traversal begins. This capability protects users from accidental broad scans and ensures the rest of the application receives validated input rather than guessing what the user meant.

## Approved behavior

- **Single-file selection:** `inspect` accepts exactly one explicitly supplied regular file, regardless of extension. A file named `component.dat` may be inspected; its suffix does not establish that it is a managed assembly.
- **Directory selection:** `scan` accepts one or more explicitly supplied directories. Candidate discovery and recursion belong to [CAP-005](CAP-005.md), not to input selection.
- **Path semantics:** Resolve relative paths against the current working directory and respect the host platform's absolute-path rules.
- **Validation before work:** Validate every explicitly supplied root before starting inspection. If any is missing, of the wrong kind, inaccessible for selection, or otherwise invalid, reject the **entire** request rather than partially processing the valid roots.
- **Explicit links:** Accept valid explicitly selected file symbolic links, directory symbolic links, and Windows junctions when their targets are valid; reject broken links.
- **No hidden expansion:** Require literal input paths. The application does not expand wildcard patterns or silently discover extra folders.
- **Actionable errors:** Explain which supplied input failed and why, without presenting a failed command as a completed scan.

## Inputs and outputs

The CLI supplies a parsed command and explicit path arguments. This capability supplies validated input information to the coordinating application use case. It must not open a file to inspect its PE metadata, enumerate child directories, or produce a scan inventory merely to validate selection.

## Boundaries and exclusions

Selection is separate from [CAP-002 assembly inspection](CAP-002.md) and [CAP-005 inventory traversal](CAP-005.md). An explicitly selected linked directory is valid input even though discovered directory links are skipped by default during recursive scans; those are different rules at different stages.

## Failure and completeness behavior

An invalid *explicit* input is a command-level failure, not an inventory item marked "unreadable." A file that becomes unreadable or disappears **after** successful validation raises the separate [input race-handling decision](../requirements/open-decisions.md); do not assume validation prevents later filesystem changes.

## Related capabilities

[CAP-007](CAP-007.md) parses user arguments, [CAP-005](CAP-005.md) coordinates the selected work, and [CAP-006](CAP-006.md) presents resulting status and diagnostics.
