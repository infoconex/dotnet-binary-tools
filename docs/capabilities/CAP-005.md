# CAP-005: Inspection Inventory

[Capability index](README.md) · [Acceptance evidence](../testing/traceability.md)

This capability document defines the approved requirement wording in its **Requirement coverage** table. The linked Given/When/Then scenarios define acceptance; explanatory material here must not expand the approved scope. [Functional requirements index](../requirements/functional.md).

## Purpose

Coordinate the work shared by one explicitly selected file and a directory inventory, safely enumerate candidates, and preserve accurate totals and completion information even when some candidates cannot be inspected. This capability owns orchestration and coverage, not the rules for reading a binary.

## Approved behavior

- **Shared inventory model:** A single-file `inspect` and a multi-root `scan` feed common aggregation and completion semantics, while retaining their different input validation requirements.
- **Candidate selection:** During directory scanning, select files by `.dll` and `.exe` extension using consistent ASCII case-insensitive matching. Do not inspect arbitrary unrelated directory entries to determine whether they might be managed assemblies.
- **Explicit scope:** Scan selected directories only, non-recursively by default. Descend into subdirectories only when requested with `--recursive`; never enumerate unrelated drives, processes, or installed applications.
- **Independent candidate findings:** Inspect and classify each candidate separately, including native/non-managed results. Do not group adjacent files into inferred applications or pair a native apphost with a neighboring DLL.
- **Continue through local failures:** Record candidate-level read/parse/permission errors and continue inspecting other candidates. Retain successfully collected facts.
- **Link handling:** An explicitly selected linked root can be valid input. During discovered traversal, skip linked subdirectories and junctions by default. With `--follow-links`, detect traversal cycles and duplicate subtree visits and explain skipped paths.
- **Deduplication:** Avoid reporting the same physical candidate twice when overlapping selected roots or followed links expose it more than once. Record deduplication in the inventory.
- **Resource controls:** Enforce documented configurable limits on traversal depth, candidate count, and file size, as well as mandatory bounded metadata parsing, time, and memory safeguards.
- **Coverage integrity:** When limits stop discovery or some candidates fail, retain available findings and mark coverage incomplete. Aggregate accurate managed/non-managed/unknown-target counts, failures, skipped paths, limits reached, and applicable lifecycle distributions.
- **Audit the selected scope:** Preserve validated roots, traversal errors, and explicit completion reasons so a reader can distinguish complete and partial results.

## Inputs and outputs

Receives validated roots from [CAP-001](CAP-001.md) and coordinates [CAP-002 metadata inspection](CAP-002.md), [CAP-003 deployment configuration](CAP-003.md), and applicable [CAP-004 lifecycle findings](CAP-004.md). Produces a structured inventory with per-candidate results, summaries, and explicit completeness metadata for [CAP-006](CAP-006.md).

## Boundaries and exclusions

No implicit application grouping, full dependency graph, installed-software discovery, or scans outside user-selected roots. Candidate filtering by extension in a directory scan does **not** limit the explicitly selected file extensions accepted by `inspect`.

## Failure and completeness behavior

Bad explicitly selected roots are rejected by [CAP-001](CAP-001.md) before work starts. In contrast, failures discovered during a valid traversal become per-file or traversal findings. A valid but incomplete report can still be generated successfully; **incomplete coverage must never be disguised as complete**.

## Open implementation decisions

Numerical defaults and allowed overrides for resource limits remain [unresolved](../requirements/open-decisions.md). The approved requirement to enforce bounds does not authorize inventing numbers.

## Related capabilities

[CAP-007](CAP-007.md) provides command options, and [CAP-006](CAP-006.md) renders inventory summaries and completeness without silently dropping failures.
